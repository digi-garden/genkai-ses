# 基本設計レビュー 第3回（V7・V8・V10・V11：技術、外部連携、性能、セキュリティ・法務）の採否整理

> レビューの判定：**条件付きで可**（必須条件は指摘1・2）
> 対象：`docs/design/01`、`06`、`08`、`09`

| # | 指摘 | 重要度 | 判定 | 対応 |
|---|---|---|---|---|
| 1 | ボタンを押してから画像を作ると、iOS Safari でユーザー操作の期限が切れ、Web Share が開かない | 高 | **採用** | 結果画像は、リザルト画面の表示時に裏で作っておく。できるまでは［画像付きでシェア］を「準備中…」にする。ボタンの処理では、クリップボードへの書き込みと `navigator.share()` を `await` をはさまずに続けて呼ぶ。画像のコピーと保存も、作成済みの画像を使うように直した（06 の 3.3、3.4、4章） |
| 2 | 投稿画面の URL が、エンコード後に2,000文字を超える | 中 | **一部採用** | 試算すると問題は起きない。シェア文は280以内（全角なら最大128文字）に収めるので、URL 全体は最悪のケースでも**約1,290文字**。レビューの「2,200〜2,600文字」は、280を全角280文字と見積もったための過大評価と思われる。実行時の判定は入れず、「最悪のケースでも2,000文字以内」を単体テストで確かめる（06 の 3.2、07 の 2.1） |
| 3 | CSP で Cloudflare Insights のサブドメインを許可していない | 中 | **不採用（別の修正あり）** | Cloudflare の公式ドキュメントが示す許可先は `script-src static.cloudflareinsights.com` と `connect-src cloudflareinsights.com` で、ワイルドカードは求められていない。許可する範囲を広げすぎないため、現状のままにする。**ただし、確認の過程で別の問題が見つかった**：ビーコンの送信先は、自動で挿入する方式（自分のドメインの `/cdn-cgi/rum`）と手動で埋め込む方式（`cloudflareinsights.com`）で異なり、06 の「管理画面で有効にすれば自動で挿入される」という前提は確実ではなかった。挙動と CSP を一意に決めるため、**JS スニペットを手動で埋め込む方式**に変えた（06 の 2.3、01 の環境変数、08 の 5.1） |
| 4 | ライブラリのバージョン指定が実際と違う可能性（zod 4 はアルファ版など） | 低 | **一部採用** | zod 4 は正式版（2026-10-31 に npm で 4.6.7 を確認）で、表の値は npm で確認した安定版。ただし、着手時に再確認し、非互換があれば1つ前の安定版にするという手順は有益なので、01 の 3章に追記した |
