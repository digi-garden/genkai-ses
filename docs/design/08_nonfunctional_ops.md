## 1. 性能

### 1.1 目標値（スマホ・4G 回線相当。Lighthouse のモバイル設定で計測）

| 指標 | 目標 |
|---|---|
| LCP（最初の主要な表示） | 2.5秒以内 |
| CLS（レイアウトのずれ） | 0.1 以下 |
| INP（操作への反応） | 200ms 以内 |
| 選択してから次のカードを操作できるまで | 0.3秒以内（要件 3.1-6） |

### 1.2 容量の予算

| 対象 | 予算（gzip 後） | 方針 |
|---|---|---|
| 最初に読む JS | **150KB 以内** | motion は `LazyMotion` ＋ `domAnimation` で必要な機能だけ読む。lucide-react はアイコンを個別に import する。実行時の検証には `zod/mini` を使う |
| 後から読む JS | 制限なし（目安 30KB） | html-to-image は、リザルト画面を開いたときに動的 import で読む |
| CSS | 20KB 以内 | Tailwind の未使用クラスは自動で削られる |
| フォント | 200KB 以内（1ファイル × 2ウェイト） | `font-display: swap`。表示を待たせない（09 検証2） |
| 話者アイコン（9枚） | 1枚 8KB 以内（実績 1〜2KB） | 2章 |
| 結末の一枚絵（9枚） | 1枚 120KB 以内（実績 21〜35KB） | 2章 |

- CI で `dist` の容量を集計し、予算を超えたら警告する（07 の 5章）。

### 1.3 画像の読み込み順（要件 7.3-4 の「起動時に17枚（v1.14 で18枚）を一括プリロード」からの変更）
- **起動時：** 話者アイコン9枚だけを先に読み込む（合計 72KB 以内。実績は約13KB。プレイ画面ですぐ使うため）。
- **最初のカードを表示した後：** 結末の一枚絵9枚を、ブラウザが空いているとき（`requestIdleCallback`）に読み込む。
- 理由：一枚絵は合計で最大約1MB になり、起動時に読むとスマホの回線で最初の表示が遅れる。一枚絵を使うのはリザルト画面だけで、最短でも数十秒後になる。
- リザルト画面の表示までに一枚絵が読み込めていなければ、最大2秒待つ。それでもだめなら仮素材の枠で表示する（要件 7.3-4 の代替表示）。

## 2. 素材（画像）の作り方

### 2.1 仕様

| 種類 | 枚数 | 完成サイズ | 描く解像度 | 形式 |
|---|---|---|---|---|
| 話者アイコン | **9**（秘書を追加。2026-11-10） | 128×128 | **64×64** で描き、2倍に拡大（2026-11-10 変更。32×32 では表情がつぶれたため） | WebP（ロスレス） |
| 結末の一枚絵 | 9 | 1280×720 | 320×180 で描き、4倍に拡大 | WebP（ロスレス。容量を超えるときは品質 90 の非可逆） |
| OGP 画像 | 9＋1（トップ用） | 1200×630 | 一枚絵から合成（06 の 5.3） | PNG |

- 拡大はニアレストネイバー（ドットがぼけない方法）で行う。ドット絵はロスレスの方が、容量も小さく劣化もない。
- 背景は、アイコンは透明、一枚絵は暗め（UI の `bg` に近い色調）にそろえる。
- 権利の確認手順は要件 4.2（v1.11）のとおり。生成の記録は `docs/asset_log.md` に残す（項目：ファイル名、使ったサービスとプラン、生成日、プロンプト、類似チェックの結果、修正の有無）。

### 2.1.1 生成ツールと手順（2026-11-01 追加）
- **ツール（2026-11-10 決定）：ChatGPT（有料プラン）に統一する。** 比較の結果（`assets_raw/compare/`）、表情が大きく縮めても読めること、結末の絵の構図がすっきりしていることから選んだ。以下は比較前の検討内容：オーナーが契約している **ChatGPT（有料プラン）または Gemini（有料プラン）** を使う（追加費用なし。どちらも有料プランで商用利用でき、生成物の権利は利用者にある）。最初に同じプロンプトで話者アイコン1枚と結末の一枚絵1枚を両方で作って比べ、**1つのツールに統一する**（画風をそろえるため）。
- **Gemini を使う場合：** 生成の前に、設定の「Media watermark」をオフにする（目に見える透かしを入れないため。2026-08-14 から設定可能。職場・学校のアカウントと一部の国では不可）。目に見えない電子透かし（SynthID）と出所のメタデータは残るが、AI 生成であることを隠す必要はないので問題ない。透かしを後から加工で消すことはしない。
- **話者アイコン：** 9人を「3列×3段、背景マゼンタの1枚の絵」として生成する（タッチと色味をそろえるため。2026-11-10 変更。横一列では1人あたりの解像度が足りなかった）。切り分けとマゼンタの透過は AI（Claude）が行う。
- **ドット絵への変換（AI が担当）：** 汎用 AI の出力はドット絵「風」で格子がそろっていないので、スクリプト（`tools/pixelize.py`、Python と Pillow。2026-11-11 実装。素材の変換は一度きりの作業でビルドには含めないため、ゲーム本体と言語をそろえる必要はないと判断）で次の処理をする。①分割・切り抜き（一枚絵は 16:9 に中央で切り抜く） ②64×64 または 320×180 へ縮小（平均で縮小し、アイコンは不透明度を2値化） ③全18枚で共通の32色パレットに減色（ディザなし）。**UI の差し色（緑 `#22C55E`、アンバー `#F59E0B`、赤 `#EF4444`）はパレットに固定で残す**（比較時、モニターの緑の光が減色で消えたため） ④ニアレストネイバーで拡大（アイコン2倍、一枚絵4倍） ⑤ロスレス WebP で保存。素材を1枚でも差し替えたら、パレットが変わるので18枚すべてを変換し直す。
- **オーナーの作業：** 生成と選択、既存作品との類似の確認、`docs/asset_log.md` の「使ったサービスとプラン、生成日、規約を確認した日」の記入。プロンプトと変換の記録は AI が書く。

### 2.2 仮素材
- 素材18枚は実装前（2026-11-11）にそろったので、**仮素材は作らない**（`npm run placeholders` は廃止）。素材は最初から `src/assets/img/` に本番のものを置く（01 の 5章。Vite がファイル名にハッシュを付ける）。
- 読み込みに失敗したときの代替表示（要件 7.3-4）は、画像ではなく CSS の枠（ファイル名を出さない、話者名だけの灰色の枠）で行う。

## 4. エラー時の動き

| 状況 | 動き |
|---|---|
| 画面の描画中の想定外のエラー | React のエラー境界で受け止め、「問題が発生しました」の画面を出す。ボタンは［タイトルに戻る］（途中データは残す）と［途中データを消してやり直す］ |
| 想定外の例外（`window.onerror`、`unhandledrejection`） | 開発者ツールのコンソールに出し、計測に `app_error` を送る（1ページにつき最大5回。内容は種類だけで、メッセージ本文や個人に関わる情報は送らない） |
| ストレージが使えない | メモリ上で続ける（06 の 1章） |
| 画像の読み込み失敗 | 仮素材の枠で表示し、コンソールに出す（要件 7.3-4） |
| 結果画像の生成失敗 | 画像なしのシェアに切り替える（06 の 4章） |
| 途中データが壊れている、または版が違う | 途中データを破棄して、タイトル画面から始める（05 の 6章） |

- サーバーにエラーを集める仕組み（Sentry など）は入れない（費用と外部送信が増えるため。PoC の段階では GA4 の `app_error` で傾向が分かれば十分）。

## 5. セキュリティ

### 5.1 HTTP ヘッダー（`public/_headers` の `/*` に設定する）

```
Content-Security-Policy: default-src 'self'; script-src 'self' https://www.googletagmanager.com https://static.cloudflareinsights.com; connect-src 'self' https://*.google-analytics.com https://*.analytics.google.com https://www.googletagmanager.com https://cloudflareinsights.com; img-src 'self' data: blob: https://*.google-analytics.com https://www.googletagmanager.com; style-src 'self' 'unsafe-inline'; font-src 'self' data:; frame-ancestors 'none'; base-uri 'self'; form-action 'none'; object-src 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(), geolocation=()
```

- `style-src 'unsafe-inline'` と `font-src data:` は、html-to-image が画像を作るときにスタイルとフォントを埋め込むために必要。
- Cloudflare Web Analytics の許可先（`script-src https://static.cloudflareinsights.com`、`connect-src https://cloudflareinsights.com`）は、Cloudflare の公式ドキュメントが示す値に合わせている（手動で埋め込む方式。06 の 2.3）。サブドメインのワイルドカードは、公式に必要とされていないので入れない（許可する範囲を広げすぎないため）。
- GA4 の読み込みは、インラインの `<script>` を使わず、アプリのコードから `<script src>` を追加する形にする（`script-src` に `'unsafe-inline'` を入れないため）。
- **公開前に、プレビュー環境で CSP の違反が出ないかを確認する**（GA4 と Cloudflare のビーコンの送信先は変わることがあるため）。

### 5.2 そのほか
- ユーザーが入力するのは会社名だけ。React の通常の描画で自動的にエスケープされる。`dangerouslySetInnerHTML` は使わない（要件 7.2-1）。
- 秘密の情報（API キーなど）は持たない。GA4 の測定 ID は公開されても問題ない値。
- 依存パッケージの脆弱性は、GitHub の Dependabot で通知を受ける。

## 6. 公開と更新の手順

### 6.1 ブランチとデプロイ
- `main`：本番。プルリクエストのマージでだけ更新する。
- 作業ブランチ：プレビュー環境（固有の URL）で確認する。プレビュー環境では GA4 を読み込まない（01 の 7.2）。
- **ビルド回数の節約（無料枠はアカウント全体で月500回・同時に1つ。基本設計レビュー第4回）：** Cloudflare Pages の設定で、次の3つを使う。
  1. **ブランチの制御**（Settings › Builds › Branch control）：本番は `main`。プレビューを自動で作るのは、名前が `preview/` で始まるブランチだけにする。確認したい作業は `preview/〇〇` ブランチで行う。
  2. **ビルドの対象パス**（build watch paths）：`src/**`、`public/**`、`tools/**`、`index.html`、`package.json`、`package-lock.json`、`vite.config.ts` が変わったときだけビルドする。`docs/**` だけの変更ではビルドしない。
  3. **コミットメッセージでの省略**：先頭に `[CI Skip]`（または `[CF-Pages-Skip]`）を付けたコミットはビルドしない。
- 月ごとのビルド回数は、Cloudflare の管理画面で確認する。300回を超えたら、プレビューの作成を控える。

### 6.2 公開前のチェック（Week 4・Week 8）
1. CI がすべて通っている（07 の 5章）。
2. シミュレータの合格基準がすべて OK（07 の 3.4）。
3. 手動確認のチェックリストを終えている（07 の 6章）。
4. プレビュー環境で、CSP の違反がない。結末ページの表がすべて期待どおり（09 検証1）。
5. 法的表記（7章）がそろっている。
6. 本番の環境変数（`VITE_GA_MEASUREMENT_ID`、`VITE_SITE_ORIGIN`）が設定されている。

### 6.3 不具合が出たとき
- Cloudflare Pages の管理画面で、1つ前のデプロイに戻す（数十秒で反映される）。その後、修正をプルリクエストで入れる。

### 6.4 カードの追加・修正の流れ
1. 作業ブランチでカード JSON を編集する。
2. `validate:cards` と `simulate --quick` を通す。
3. プルリクエストを作り、プレビュー環境で実際に遊んで確認する。
4. マージして公開する。
- 一度公開したカード ID は、削除しても再利用しない（05 の 2章）。カードデータが変わると、プレイ途中のデータは破棄される（05 の 6章）ので、大きな更新は利用の少ない時間帯に行う。

## 7. 法的表記（M03 の中身の構成）

- **作り方（基本設計レビュー第4回）：** ゼロから書かず、個人開発向けの一般的な雛形（利用規約・プライバシーポリシーのジェネレーターなど）を土台に、下表の内容と 06 の 6章（外部送信の一覧）を当てはめる。下書きは AI に作らせてよいが、最終的な文面はオーナーが確認する（法的な助言ではないので、気になる点は専門家に相談する）。
- **時期：** バランス調整で忙しい Week 4 を避け、**Week 2〜3 の空き時間に下書きを作る**。Week 4 には確認と最終化だけを行う。

| 見出し | 書くこと |
|---|---|
| 利用規約 | 本作の利用条件、禁止事項（実在の企業・人物を中傷する目的での利用、結果画像の改変による誤解を招く投稿など）、免責、著作権（素材とテキストの権利は運営者に帰属）、規約の変更 |
| プライバシーポリシー | 取得する情報（06 の 6章の表）、端末内に保存する情報（SaveData の内容。運営者には送られないこと）、外部送信の一覧、同意の変更方法（EEA など）、問い合わせ先 |
| 免責事項 | フィクションである旨（要件 1.）、会社名はプレイヤーが入力した架空の名称である旨、法令違反や不当な労働行為を推奨しない旨 |
| 運営者 | 運営者の名前（ハンドルネーム可）と連絡先 |

- **お問い合わせ（M04）：** Google フォームへのリンクにする。入力項目は「内容」（必須）と「返信先」（任意）だけにし、個人情報を求めない。NG 社名の追加の依頼も、ここで受け付ける。

## 8. 公開後の運用

| 頻度 | 作業 |
|---|---|
| 毎日（公開から1週間） | GA4 のリアルタイムと `app_error` を見る。X で「#限界SES社長」の反応を見る |
| 毎週 | KPI（要件 1.1 の5指標と、GA4 の捕捉率）を記録する。死因の比率を、シミュレータの予測と比べる |
| 公開から2〜4週間後 | Go / No-Go を判定する（要件 1.1） |
| 随時 | 問い合わせに対応する。NG 社名リストに追加する |

- 費用：Cloudflare Pages（無料枠：ビルドは**アカウント全体で**月500回、同時に1つまで。静的な配信は回数・量とも無制限。プレビュー環境のビルドも回数に含まれる）、Cloudflare Web Analytics、GA4 はどれも無料。独自ドメインを取らなければ、運用費は **0円**。
