# 基本設計レビュー 第1回（V1・V2：要件との対応、資料の整合）の採否整理

> レビューの判定：**条件付きで可**（必須条件は指摘1・2）
> 対象：`docs/design/00〜10`、`requirements_v1.12.md`

| # | 指摘 | 重要度 | 判定 | 対応 |
|---|---|---|---|---|
| 1 | 02 に6章がなく、長い文言のときの表示の動きが決まっていない | 高 | **一部採用** | 6章は実在する（`02_screen_design.md` の 160行目「6. 文言の長さの上限」）。レビュアーの読み落としと思われる。ただし「上限いっぱいの文言が、最小の画面（360×640）でどう表示されるか」が決まっていなかったのは事実なので、6.1（折り返し・行数・文字サイズ）と 6.2（縦に収まらないときの動き）を追加した。試算では最小の画面でもスクロールなしで収まる。収まらない場合は、カードの本文だけをスクロールさせる |
| 2 | シェア文の調整で、称号と敗因が先に削られる | 中 | **採用** | 調整の順番を「挑戦状を短く → 挑戦状を省く → 会社名を切る → 敗因を切る → 称号を省く」に変えた（06 の 3.2）。最悪のケースの試算でも、3段階目までで収まり、称号と敗因は残る |
| 3 | `heartbeat_sent` の追加が、要件への反映事項として記録されていない | 中 | **不採用** | `heartbeat_sent` は要件書 v1.12 の時点で SaveData に入っている（`requirements_v1.12.md` の 362行目）。設計で追加したものではないため、反映事項に載せる必要はない |
| 4 | 倒産の演出（0.6秒）が、テンポの要件の例外として記録されていない | 中 | **採用** | 00 の 3.1 に R10 として追加した |
| 5 | カード JSON の効果値で、0 を毎回書くのが手間 | 低 | **採用（補強）** | 変化しない項目は省略でき、読み込み時に 0 を補う（`.default(0)`）。省略を許すと書き間違い（例：`lgal`）が黙って無視されるおそれがあるので、4つ以外のキーはエラーにする（`z.strictObject`）（05 の 3.3） |
