# 第3回レビュー（v1.9 変更点の再レビュー）の採否整理

> レビューの判定：**条件付きで可**（必須条件は指摘A・B）
> 依頼1（前回の指摘1〜8の解消確認）：8件すべて「解消」

| # | 指摘 | 重要度 | 判定 | 対応（v1.10） |
|---|---|---|---|---|
| A | ドロー優先順位の記述順と評価順が一致しない | 高 | **採用** | 3.1-6 を「上から評価する」順序（導入 → 季節固定 → 連鎖 → 通常）に書き直した。季節固定と連鎖が同じ週に重ならないことも明記した |
| B | 死因比率「各5〜25%」は上限死に対して非現実的 | 中 | **採用** | 下限死は各5〜25%、上限死は各1〜15%（合計10〜30%）に分けた。3.1-2 の指針にも「上限死はやや希少」と追記した |
| C | スマホでの切り札の操作が定義されていない | 中 | **採用（補強）** | 1回目で確認状態、2回目で発動とした。取り消し操作を定義し、長押しは使わない。補強として、2択を操作したときは取り消しと同時に選択として受け付け、操作が1回無駄にならないようにした |
| D | 敗因表示がほとんど出ない | 中 | **採用（条件を追加）** | 案A（3ターン以内）を採用した。ただし、無関係な死因に敗因が付くのを防ぐため、「その連鎖カードが、死因となったパラメータを死因の向きに動かしていた」ことも条件に加えた |
| E | 77枚＋シミュレータで工数が危険水域 | 中 | **修正して採用** | MVPの77枚はオーナーの決定を維持した。そのうえで「Week 3 の終了時点で遅れていたら、スタイル別15枚を延期（MVPは62枚）」という削減ラインを明記した（レビューの総評にある「バッファを持っておく」案と同じ） |
| F | 初回の未読優先と序盤カード優先の組み合わせが曖昧 | 低 | **採用** | 山札の構築手順を5ステップで一意に定義した（初回は opening を前に、2回目以降は未読を前に、再シャッフル時は区別しない、表示した時点で既読にする） |

## 結論
移行の必須条件（A・B）を満たしたので、**v1.10 で要件定義を完了とし、基本設計に進める状態**とする。
