# 第5回レビュー（観点5・6・11：グロースと事業性）の採否整理

> 対象：`requirements_v1.11.md`

| # | 指摘 | 重要度 | 判定 | 対応（v1.12） |
|---|---|---|---|---|
| 1 | 広告ブロッカーで GA4 の数値が欠け、Go/No-Go を誤判定する | 高 | **採用（補強）** | 比率で判定する指標は、分母と分子をどちらも GA4 で取る（1.1 の計測原則、7.4 の算出式）。補強として、GA4 の捕捉率（GA4 のユーザー数 ÷ Cloudflare の UU）を記録し、絶対数を推定するときの割り戻しに使う。案B（自前の集計エンドポイント）は採用しない（工数、および Functions と KV の運用が増えるため） |
| 2 | K ≧ 0.2 の前提（1投稿あたり流入4人）が過大 | 高 | **採用（オーナー決定）** | 判定基準を「リザルト到達者のシェア率 5% 以上」に変更した。K 値は参考指標として記録する。指摘で挙がった流入数の推定値（1投稿あたり0.3〜0.8人）は根拠が示されていないため、要件書には書いていない |
| 3 | Web Share API で画像を共有すると、テキストと URL が消えることがある | 中 | **採用（A＋B＋補強）** | 画像にゲームの URL を印字する（A）。モバイルでも［Xでポスト］を主ボタンにする（B）。補強として、［画像付きでシェア］を押したときは、シェア文をあらかじめクリップボードにコピーする |
| 4 | プレイ中の延命に使うリワード広告は、テンポとシェア価値を壊す | 中 | **採用** | アプリ版のリワード広告は、プレイの外の特典（図鑑の拡張など）に限定する。巻き戻しと切り札の再装填は削除した。次のランを有利にする特典は、検証したうえで「特典あり」と記録に表示する場合に限って候補とした |
| 5 | 「開始10秒の即時離脱を除外」を集計する方法がない | 中 | **採用** | `heartbeat_10s`（ユーザーにつき1回、ページが表示中の時間で数える）を追加し、SaveData に送信済みフラグを追加した |
| 6 | 開発記事の執筆がロードマップから漏れている | 低 | **採用** | Week 7 に下書き、Week 8 に仕上げと公開予約を入れた（計4〜6時間） |

## 補足
- 指摘1の「広告ブロッカーの利用率30〜40%以上」、指摘2の「インプレッション50〜100」は、レビュアーの推定値である（出典は示されていない）。判定の仕組みはこれらの数値に依存しない形にしたので、実測値は公開後に捕捉率と流入数として記録する。
- 7.4-4 の KPI 算出式（GA4 内で完結）を、1.1 の各指標と1対1で対応させた。

## 今後
- 残っている観点：7〜10（技術・UX・性能・工数）。基本設計とほぼ重なるので、基本設計書のレビューとまとめて依頼するのが効率的。
